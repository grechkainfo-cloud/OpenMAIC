# OpenMAIC — корпоративная сборка

Форк [THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC), адаптируемый под
развёртывание в закрытом контуре: локальная модель через OpenAI-совместимый
эндпойнт, обратный прокси nginx, домен Active Directory, интерфейс на русском
языке, порядка десяти одновременных пользователей.

Продукт остаётся тем же: генерация интерактивного урока по текстовому запросу и
его воспроизведение в «классе» — слайды, закадровая речь, доска, квизы,
проектная работа, обсуждение нескольких агентов.

## Чем эта сборка отличается от апстрима

| | |
| --- | --- |
| **Бренд** | Название, палитра, шрифты, логотипы задаются в `lib/brand/brand-config.ts` и файлах `public/brand/`. В компонентах нет зашитых названий и цветов. См. [`docs/branding.md`](docs/branding.md). |
| **Язык** | Интерфейс — русский по умолчанию, английский как запасной. Остальные локали апстрима удалены. Язык интерфейса задаёт и язык генерируемого курса. |
| **Внешние ресурсы** | KaTeX, воркер pdf.js, шрифты и прочая статика вендорятся в `public/vendor/` на сборке. В рантайме обращений к CDN нет — код работает без интернета. |
| **Апстрим-артефакты** | Материалы публичного проекта (шаблоны issue, триаж, публикация в npm/ClawHub, сайт документации, демо-GIF, ссылки на сообщества) удалены — в закрытом контуре они ведут в никуда. |
| **Дальше по плану** | Слой идентичности, разделение данных между пользователями, Kerberos/SPNEGO за nginx — см. `docs/plan/`. |

## Локальный запуск для разработки

Нужны Node.js >= 22.19.0 и pnpm.

```bash
pnpm install                 # собирает workspace-пакеты и вендорит статику
cp .env.example .env.local   # заполнить эндпойнт модели и ключи
pnpm dev                     # http://localhost:3000
```

Продакшен-сборка:

```bash
pnpm build
pnpm start
```

Секреты живут только в переменных окружения и никогда — в переменных с
префиксом `NEXT_PUBLIC_`: они попадают в клиентский бандл.

Без `NEXT_PUBLIC_PERSISTENCE` приложение хранит данные в браузере и не требует
базы. Серверное хранение включается PostgreSQL-провайдером — см. `.env.example`.

## Развёртывание в закрытом контуре

Приложение собирается снаружи, переносится образом и подключается к сервисам,
которые в контуре уже развёрнуты: Qwen3, MinerU, PostgreSQL. Ниже — весь путь.
Подробности, обоснования и процедура обновления — в
[`docs/deploy-offline.md`](docs/deploy-offline.md).

### Моделей в образе нет

Это первое, что стоит понять, прежде чем планировать перенос. OpenMAIC — клиент,
а не хостинг моделей: ни одного локального инференс-движка, ни одного файла
весов. LLM, TTS, ASR, генерация изображений и видео, парсинг PDF — всё это
внешние HTTP-сервисы, адреса которых задаются переменными `*_BASE_URL`.

Поэтому переносится **один образ приложения** (500–700 МБ) и, если нужен экспорт
MP4, второй — `render-service`. Весов в комплекте нет вовсе.

pgvector приложению не нужен: эмбеддингов и векторного поиска в нём нет.
Расширение в базе не мешает, но и не используется.

### Что нужно собрать до начала

| Что | Зачем |
|---|---|
| Адрес и порт vLLM с Qwen3 | `QWEN_BASE_URL` |
| Запущен ли vLLM с `--api-key` и каким | см. предупреждение ниже — без ключа слот не поднимется |
| Точный `id` модели из `GET /v1/models` | `QWEN_MODELS`; не маркетинговое название |
| Адрес MinerU | `PDF_MINERU_BASE_URL` |
| Строка подключения к PostgreSQL | `DATABASE_URL`, плюс договорённость с администраторами СУБД |
| Корневой сертификат внутреннего УЦ | `certs/corporate-ca.crt`, если сервисы работают по HTTPS |
| Зеркало Alpine и прокси npm, если есть | `ALPINE_MIRROR`, `NPM_REGISTRY` — позволят пересобирать образ внутри контура |

### Решения, которые принимаются на сборке

Переменные с префиксом `NEXT_PUBLIC_` компилируются в браузерный бандл. Их
нельзя изменить правкой `.env.local` на стенде — только пересборкой образа.

| Флаг | Что включает |
|---|---|
| `NEXT_PUBLIC_PERSISTENCE` | серверное хранение вместо браузерного |
| `NEXT_PUBLIC_ENABLE_PPTX_IMPORT` | импорт `.pptx` |
| `NEXT_PUBLIC_PRO_WORKBENCH_ENABLED` | pro-режим с агентом |
| `NEXT_PUBLIC_ENABLE_VIDEO_EXPORT` | пункт «Экспорт видео» в меню |
| `ALLOWED_FRAME_ANCESTORS` | кому разрешено встраивать приложение в iframe |

> **Серверное хранение до фазы 3 не изолирует пользователей.** Текущая
> аутентификация персистентности — общий токен, владелец данных приходит от
> клиента, поэтому любой автор может прочитать и изменить чужой курс. Именно
> поэтому `NODE_ENV=production` отказывается работать с этой схемой без явного
> `PERSISTENCE_ALLOW_INSECURE_DEV_AUTH=true`. Если десять человек не должны
> видеть работу друг друга — собирайте без `NEXT_PUBLIC_PERSISTENCE`, оставайтесь
> на браузерном хранении и беритесь за фазу 3. Подключать PostgreSQL до неё
> смысла нет.

### Сборка и перенос

На машине с интернетом:

```bash
export OPENMAIC_IMAGE_TAG=2026.09.18        # дата или номер релиза, не latest
docker compose build                         # приложение
docker compose --profile video-export build  # плюс render-service, если нужен

docker save openmaic/app:$OPENMAIC_IMAGE_TAG -o openmaic-app-$OPENMAIC_IMAGE_TAG.tar
sha256sum openmaic-*.tar > openmaic-$OPENMAIC_IMAGE_TAG.sha256
```

Тег обязателен и должен быть говорящим: `latest` на приёмной стороне не даёт ни
проверить, что приехало, ни откатиться.

На приёмной стороне — сверить суммы **до** загрузки, затем `docker load`.

### Настройка на стенде

```
/opt/openmaic/
├── docker-compose.contour.yml     из репозитория
├── .env.local                     из .env.contour.example — ОБЯЗАТЕЛЕН
├── server-providers.yml           из server-providers.example.yml — опционально
└── certs/corporate-ca.crt         корневой сертификат — только при HTTPS
```

Без `.env.local` запуск падает сразу: `env file … not found`. Два других файла
опциональны, их монтирование в compose закомментировано — если источника
bind-mount нет, Docker создаёт на его месте каталог, и приложение падает далеко
от причины. Раскомментируйте строки тогда же, когда создадите сами файлы.

`.env.local` и `server-providers.yml` содержат секреты: права `0600`, владелец —
учётная запись, от которой запускается docker. Ни один из них не попадает ни в
git, ни в образ.

Оба шаблона снабжены комментариями по каждому значению — заполняются по ним.
Три вещи, на которых спотыкаются чаще всего:

1. **`QWEN_API_KEY` обязан быть непустым.** На одном базовом URL активируются
   только слоты `ollama`, `lemonade` и `bedrock`; `qwen` без ключа молча
   пропускается, и провайдер остаётся неуправляемым. Запускайте vLLM с
   `--api-key`. Если он уже работает без ключа — используйте `OLLAMA_BASE_URL`
   и `OLLAMA_MODELS`: транспорт тот же, но в интерфейсе появится «Ollama» с
   чужим логотипом.
2. **Приложение само создаёт схему в PostgreSQL.** При старте выполняется
   `ensureSchema()` — таблицы заводятся через `CREATE TABLE IF NOT EXISTS`.
   Учётной записи нужны права DDL хотя бы на первый запуск; «только DML» не
   заработает. Префикса таблиц и переключения схем в коде нет, поэтому нужна
   отдельная база — или изоляция через `?options=-c%20search_path%3Dopenmaic`.
3. **`ALLOW_LOCAL_NETWORKS` включать не надо.** Ни LLM, ни MinerU, ни
   render-service в нём не нуждаются: к серверно настроенным провайдерам
   SSRF-политика не применяется. Флаг нужен, только если пользователи вводят
   базовый URL руками в настройках браузера.

Корпоративный CA монтируется только на чтение, `NODE_EXTRA_CA_CERTS` выставляет
compose-файл. Это единственный работающий способ: переменную читает сам Node,
поэтому её одинаково видят и транспорт LLM, и драйвер PostgreSQL. В образ
сертификат не встраиваем — это настройка площадки, а не свойство артефакта.

### Запуск

```bash
cd /opt/openmaic
export OPENMAIC_IMAGE_TAG=2026.09.18
docker compose -f docker-compose.contour.yml up -d
docker compose -f docker-compose.contour.yml ps      # healthy?
```

Приложение слушает `127.0.0.1:3000`; наружу его публикует nginx. Напрямую порт
не выставляется: до фазы 5 у приложения нет собственной аутентификации, и
единственное, что стоит между ним и пользователями, — обратный прокси.
Состояние апстрима прокси берёт из `/api/health`.

### Приёмочная проверка

До того как пускать людей — шесть сценариев, каждый проверяет свой узел:
генерация короткого курса на русском (LLM), озвучка сцены (TTS), импорт `.pptx`
с векторной графикой (вендоренный воркер pdf.js), сцена с формулой (вендоренный
KaTeX), экспорт PPTX и ZIP (шрифты и ассеты внутри), загрузка PDF (MinerU).

Если что-то не работает — смотрите логи контейнера: недостающие сервисы
приложение называет явно, а не подставляет облако молча.

### Вход в приложение

Тип авторизации задаётся переменной `AUTH_PROVIDER`:

| Значение | Что это |
|---|---|
| `none` (по умолчанию) | входа нет — поведение до появления слоя идентичности; локальная разработка и браузерное хранение остаются как были |
| `test` | имя и пароль из переменных окружения. Одна учётная запись, для тестового стенда |
| `windows` | Kerberos/SPNEGO против Active Directory. Пока не реализовано, выбор падает на старте |

Неизвестное значение тоже падает на старте, а не превращается молча в `none`:
опечатка в `AUTH_PROVIDER` не должна выключать авторизацию.

```
AUTH_PROVIDER=test
AUTH_SESSION_SECRET=<openssl rand -base64 48>
AUTH_TEST_USERNAME=<переопределите>
AUTH_TEST_PASSWORD=<переопределите>
AUTH_TEST_ALLOW_IN_PRODUCTION=true
```

`AUTH_SESSION_SECRET` обязателен: без него приложение не стартует. Кто им
владеет — может выписать сессию любому пользователю, поэтому он живёт только в
переменных окружения и никогда в `NEXT_PUBLIC_*`.

По умолчанию провайдер `test` принимает `admin` / `admin`. Эту пару знает
каждый, кто видел проект, поэтому при `NODE_ENV=production` — а контейнер
запускается именно так — она отвергается без явного
`AUTH_TEST_ALLOW_IN_PRODUCTION=true`, и при старте с ней в лог уходит
предупреждение. На стенде, до которого дотягивается кто-то кроме вас, имя и
пароль надо переопределить.

Что `test` **не** делает: это одна учётная запись, а не каталог пользователей.
Он ограничивает вход, но не разделяет данные — разграничение приходит в фазе 4.
Смысл провайдера в том, чтобы весь слой идентичности — сессия, экран входа,
привязка данных к владельцу, роли — был собран и отлажен до того, как станет
доступен домен.

Если задан и `AUTH_PROVIDER`, и `ACCESS_CODE`, общий код доступа игнорируется:
идентичность старше общего пароля. При старте об этом пишется предупреждение.

### Чего ещё нет

- **Фаза 3** — слой идентичности: провайдер `test` готов, `windows` (Kerberos)
  ещё нет.
- **Фаза 4** — разделение данных между пользователями.
- **Фаза 5** — Kerberos/SPNEGO за nginx.
- Конфигурация самого nginx (TLS, таймауты для длинных SSE-ответов генерации,
  заголовки) — отдельная задача, в репозитории не описана.

## Проверки

CI гоняет то же самое; локально дешевле поймать раньше.

```bash
pnpm format                  # prettier --write
pnpm lint --fix
npx tsc --noEmit
pnpm check:i18n-keys         # ключи локалей + формы множественного числа
pnpm check:brand-contrast    # WCAG-контраст токенов темы
pnpm check:brand-fonts       # покрытие кириллицы объявленными шрифтами
pnpm test                    # vitest
pnpm test:e2e                # playwright
```

Правила, которые стоит держать в голове при правках:

- любой текст, видимый пользователю, идёт через i18n — строк в коде не зашиваем;
- добавили или переименовали переменную окружения — обновите `.env.example` в
  том же коммите, с пометкой, читается она на сборке или в рантайме;
- сообщения коммитов — [Conventional Commits](https://www.conventionalcommits.org/):
  `feat(scope): ...`, `fix(scope): ...`, `docs(scope): ...`.

## Ключевые узлы

- **Конвейер генерации** (`@openmaic/generation`) — два этапа: план урока →
  содержимое сцен.
- **Рантайм агента** (`lib/server/agent-runtime/`) — сессии в PostgreSQL с
  арендой исполнения, возобновлением и корректировкой хода.
- **Слой хранения** (`@openmaic/storage`) — сменные хранилища документов,
  рантайма, KV, ассетов, сессий агента, материалов и пользовательских навыков.
- **Оркестрация** (`lib/orchestration/`) — автомат LangGraph, управляющий
  очередью реплик агентов.
- **Воспроизведение** (`lib/playback/`) — автомат, ведущий урок и живое
  взаимодействие.
- **Движок действий** (`lib/action/`) — исполняет более 28 типов действий (речь,
  рисование и текст на доске, диаграммы, подсветка, лазер …).
