# Развёртывание в закрытом контуре

Сборка образа снаружи, перенос носителем, подключение к сервисам, которые в
контуре уже есть: Qwen3, MinerU, PostgreSQL.

Разбор, почему сделано именно так, — в [`plan/offline-image.md`](plan/offline-image.md).

---

## 0. Что переносим и чего не переносим

Моделей и весов в образе нет: приложение — клиент, а не хостинг моделей.
Ни одного локального инференс-движка в нём не содержится, всё подключается по
HTTP. Раз Qwen3 и MinerU уже развёрнуты, переносить нужно **один образ**, и
второй — только если нужен экспорт MP4.

| Компонент | Откуда берётся |
|---|---|
| Приложение | образ собирается снаружи и переносится |
| render-service | то же, но только при необходимости экспорта MP4 |
| Qwen3, MinerU, PostgreSQL | уже в контуре, подключаются конфигурацией |

pgvector приложению не нужен: эмбеддингов и векторного поиска в нём нет.
Расширение в базе не мешает.

## 1. Сборка (машина с интернетом)

### 1.1 Решения, которые принимаются на сборке, а не потом

Переменные с префиксом `NEXT_PUBLIC_` компилируются в браузерный бандл. Их
**нельзя** поменять правкой `.env.local` на стенде — только пересборкой. Поэтому
решайте до сборки:

| Флаг | Что включает |
|---|---|
| `NEXT_PUBLIC_PERSISTENCE` | серверное хранение вместо браузерного (см. §3.4 — до фаз 3–4 без изоляции пользователей) |
| `NEXT_PUBLIC_ENABLE_PPTX_IMPORT` | импорт `.pptx` |
| `NEXT_PUBLIC_PRO_WORKBENCH_ENABLED` | pro-режим с агентом |
| `NEXT_PUBLIC_ENABLE_VIDEO_EXPORT` | пункт «Экспорт видео» в меню |
| `ALLOWED_FRAME_ANCESTORS` | кто имеет право встраивать приложение в iframe |

### 1.2 Собственно сборка

```bash
export OPENMAIC_IMAGE_TAG=2026.09.18        # дата или номер релиза, не "latest"
docker compose build                         # приложение
docker compose --profile video-export build  # плюс render-service, если нужен
```

Тег обязателен и должен быть говорящим. `latest` на приёмной стороне не
позволяет ни проверить, что приехало, ни откатиться.

### 1.3 Воспроизводимость

Базовый образ закреплён на точной версии (`node:22.22.2-alpine`), но не на
digest — digest читается из реестра, и вписать его вслепую нельзя. На машине с
Docker закрепите жёстче:

```bash
docker buildx imagetools inspect node:22.22.2-alpine   # покажет digest
docker build --build-arg NODE_IMAGE=node:22.22.2-alpine@sha256:<digest> .
```

Системные пакеты Alpine версиями не закреплены: `apk` тянет текущий индекс с
`dl-cdn.alpinelinux.org`, и он меняется. Если в организации есть зеркало Alpine,
передайте его — тогда состав пакетов контролируете вы:

```bash
docker compose build --build-arg ALPINE_MIRROR=alpine.example.corp \
                     --build-arg NPM_REGISTRY=https://nexus.example.corp/repository/npm
```

Те же два аргумента позволяют пересобирать образ **внутри** контура, если
зеркала есть.

### 1.4 Выгрузка

```bash
docker save openmaic/app:$OPENMAIC_IMAGE_TAG            -o openmaic-app-$OPENMAIC_IMAGE_TAG.tar
docker save openmaic/render-service:$OPENMAIC_IMAGE_TAG -o openmaic-render-$OPENMAIC_IMAGE_TAG.tar
sha256sum openmaic-*.tar > openmaic-$OPENMAIC_IMAGE_TAG.sha256
```

Отдельными файлами, а не одним общим: приложение обновляется часто, служба
рендера почти никогда, и таскать её каждый раз незачем.

## 2. Перенос

1. носителем переносим `.tar` и файл контрольных сумм;
2. на приёмной стороне сверяем суммы **до** загрузки:
   `sha256sum -c openmaic-<тег>.sha256`;
3. `docker load -i openmaic-app-<тег>.tar`;
4. `docker images openmaic/app` — убеждаемся, что тег тот самый.

`docker load` восстанавливает образ под тем именем, с которым он сохранён,
поэтому `OPENMAIC_IMAGE_TAG` на стенде должен совпадать с тегом сборки. Если не
совпадает — `docker compose up` сообщит, что образа нет, и **никуда за ним не
пойдёт**: в contour-файле у обоих сервисов стоит `pull_policy: never`. Это
намеренно. Без него отсутствующий локально образ отправляет Docker в Docker Hub,
где `openmaic/app` — чужое пространство имён, и вместо внятного «образа нет»
получается `pull access denied`.

Частый случай: собрали без `OPENMAIC_IMAGE_TAG`, получили `openmaic/app:dev`,
а запускаете с датой. Лечится переименованием:

```bash
docker images openmaic/app                          # что на самом деле есть
docker tag openmaic/app:dev openmaic/app:2026.09.18
```

## 3. Настройка на стенде

### 3.1 Файлы

```
/opt/openmaic/
├── docker-compose.contour.yml     из репозитория
├── .env.local                     из .env.contour.example — ОБЯЗАТЕЛЕН
├── server-providers.yml           из server-providers.example.yml — опционально
└── certs/corporate-ca.crt         корневой сертификат — только при HTTPS
```

**`.env.local` обязателен**: без него `docker compose up` падает сразу, ещё до
запуска контейнера, с сообщением `env file … not found`.

Два других файла опциональны, и монтирование обоих в compose-файле закомментировано.
Причина практическая: если источник bind-mount отсутствует, Docker создаёт на его
месте **каталог**, и приложение падает уже далеко от причины — на «сертификате»,
который оказался директорией. Раскомментируйте строки монтирования тогда же,
когда создадите сами файлы:

- `server-providers.yml` — когда хотите задать провайдеров файлом, а не
  переменными окружения (для LLM и PDF это предпочтительнее: серверно
  настроенному провайдеру доверяется приватный адрес);
- `certs/corporate-ca.crt` вместе с `NODE_EXTRA_CA_CERTS` — когда сервисы
  контура работают по HTTPS с сертификатом внутреннего УЦ.

`.env.local` и `server-providers.yml` содержат секреты: права `0600`, владелец —
учётная запись, от которой запускается docker, и ни один из них не попадает ни
в git, ни в образ.

### 3.2 Qwen3

```
QWEN_BASE_URL=http://vllm.example.corp:8000/v1
QWEN_API_KEY=<токен, которым запущен vLLM>
QWEN_MODELS=<id из GET /v1/models>
```

**Ключ обязан быть непустым.** На базовом URL без ключа активируются только
слоты `ollama`, `lemonade` и `bedrock`; `qwen` без ключа будет пропущен, и
провайдер останется неуправляемым. Запускайте vLLM с `--api-key`. Если он уже
работает без ключа — используйте `OLLAMA_BASE_URL` и `OLLAMA_MODELS`: транспорт
тот же, но в интерфейсе появится «Ollama» с чужим логотипом.

Частный адрес (10.x, 172.16.x, 192.168.x) здесь проходит без дополнительных
разрешений: транспорт LLM не применяет адресную политику.

### 3.3 MinerU

```
PDF_MINERU_BASE_URL=http://mineru.example.corp:8080
PDF_MINERU_BACKEND=pipeline
ALLOW_MINERU_CLOUD_FALLBACK=
```

Последнюю строку оставляем пустой. Запрос к своему MinerU никогда не уходит в
облако молча — при неверной настройке он падает с явной ошибкой. Значение
`true` разрешило бы документам покидать контур.

### 3.4 PostgreSQL

```
DATABASE_URL=postgres://openmaic:<пароль>@postgres.example.corp:5432/openmaic?sslmode=require
```

Что нужно согласовать с администраторами СУБД — и лучше письмом, а не устно:

1. **Приложение само создаёт схему.** При старте выполняется `ensureSchema()`,
   таблицы заводятся через `CREATE TABLE IF NOT EXISTS`. Учётной записи нужны
   права DDL хотя бы на первый запуск; «только DML» не заработает. Если политика
   запрещает DDL приложению — схему создаёт администратор вручную, и тогда
   **каждое обновление, добавляющее таблицу, требует повторения процедуры**.
   Это нужно зафиксировать, иначе оно всплывёт в самый неудачный момент.
2. **Отдельная база.** Префикса таблиц и переключения схем в коде нет —
   приложение считает базу своей. Если выделенную базу не дают, изоляция через
   `?options=-c%20search_path%3Dopenmaic`.
3. **TLS.** Режим задаётся в строке подключения. Проверка сертификата
   внутреннего УЦ работает только через `NODE_EXTRA_CA_CERTS` — см. §3.5.

Про серверное хранение: **до фаз 3 и 4 изоляции пользователей нет.** Текущая
аутентификация персистентности — общий токен, владелец приходит от клиента,
поэтому любой автор может прочитать и изменить чужой курс. Именно поэтому
`NODE_ENV=production` отказывается работать с этой схемой без явного
`PERSISTENCE_ALLOW_INSECURE_DEV_AUTH=true`. Если десять человек не должны
видеть работу друг друга — до фазы 3 оставайтесь на браузерном хранении.

### 3.5 Корпоративный CA

Нужен, только если сервисы контура работают по HTTPS с сертификатом внутреннего
УЦ. Кладём его в `certs/corporate-ca.crt` и раскомментируем в
`docker-compose.contour.yml` две строки: монтирование и `NODE_EXTRA_CA_CERTS`.
Обе закомментированы по умолчанию, потому что отсутствующий источник
bind-mount Docker подменяет каталогом.

Это единственный поддерживаемый способ: переменную читает сам Node, поэтому её
одинаково видят и undici (LLM, MinerU), и node-postgres. Переменная ждёт
**файл**, а не каталог; если внутренний УЦ подписан промежуточным — в файле
должна лежать вся цепочка.

В образ сертификат не встраиваем: это настройка площадки, а образ с чужими
корнями доверия перестаёт быть тем же артефактом, который проверяли.

### 3.6 Провайдеры, которых в контуре нет

Лишние провайдеры в списке — это приглашение ввести ключ и удивиться таймауту.
`enabled: false` в `server-providers.yml` выключает провайдера для всех
клиентов, но работает **только** для разделов `tts`, `asr`, `image`, `video` и
`web-search`. Для LLM и PDF такого выключателя нет: провайдер без учётных данных
просто остаётся неуправляемым, но из интерфейса не исчезает.

## 4. Запуск

```bash
cd /opt/openmaic
export OPENMAIC_IMAGE_TAG=2026.09.18
docker compose -f docker-compose.contour.yml up -d
docker compose -f docker-compose.contour.yml ps      # healthy?
docker compose -f docker-compose.contour.yml logs -f openmaic
```

`OPENMAIC_IMAGE_TAG` обязателен: без него compose останавливается с подсказкой,
а не поднимает что-нибудь наугад.

### 4.1 Порт и доступ

Контейнер слушает **3000**, и contour-файл публикует его только на петле:
`127.0.0.1:3000:3000`. С самой машины приложение доступно, из сети — нет, и это
намеренно. До фазы 5 у приложения нет доменной аутентификации, и единственное,
что должно стоять между ним и пользователями, — nginx.

```bash
curl -s localhost:3000/api/health
```

Пока nginx не поднят, зайти с другой машины можно пробросом по SSH, ничего не
открывая в сети:

```bash
ssh -L 3000:127.0.0.1:3000 <пользователь>@<адрес-стенда>
```

Если нужно именно открыть порт в сеть — адрес привязки задаётся переменной,
править compose-файл не надо:

```bash
OPENMAIC_IMAGE_TAG=2026.09.18 OPENMAIC_BIND_ADDRESS=0.0.0.0   docker compose -f docker-compose.contour.yml up -d
```

Переменная читается на этапе подстановки, то есть из окружения команды или из
файла `.env` в каталоге проекта — **не** из `.env.local`: тот передаётся внутрь
контейнера и на публикацию портов не влияет.

Два следствия, о которых надо знать заранее:

- `COOKIE_SECURE=0` в `.env.local` становится обязательным. По адресу вида
  `http://10.0.0.5:3000` браузер не сохранит сессионную cookie с флагом
  `Secure`, и вход зациклится. Для `localhost` Chrome делает исключение, для
  адреса в сети — нет;
- стенд становится доступен всем, кто дотянется до хоста, а перед ним стоит
  одна общая пара логин-пароль. На день проверки это нормально, как режим
  работы — нет. На хостах с firewalld порт всё равно придётся открыть отдельно
  (`firewall-cmd --add-port=3000/tcp`).

Левую часть публикации можно менять — контейнер всегда слушает 3000:
`OPENMAIC_BIND_ADDRESS=0.0.0.0` плюс правка на `8080:3000` даст внешний 8080.

Состояние апстрима прокси берёт из `/api/health`: ответ без авторизации, без
обращений к базе, годится для частого опроса. По нему же работает healthcheck
контейнера, поэтому `ps` показывает `healthy` только когда приложение
действительно отвечает.

### 4.2 Пробный запуск до подключения сервисов

Проверить, что образ жив и вход работает, можно раньше, чем настроены Qwen3,
MinerU и база. Минимальный `.env.local`:

```bash
cp .env.contour.example .env.local
chmod 600 .env.local

cat >> .env.local <<EOF
AUTH_PROVIDER=test
AUTH_SESSION_SECRET=$(openssl rand -base64 48)
AUTH_TEST_ALLOW_IN_PRODUCTION=true
COOKIE_SECURE=0
EOF
```

- `AUTH_TEST_ALLOW_IN_PRODUCTION` нужен потому, что в образе стоит
  `NODE_ENV=production`, и пара `admin`/`admin` там отвергается без явного
  согласия. Это и есть тот осознанный опт-ин.
- `COOKIE_SECURE=0` нужен, **пока стенд открыт по http**. Иначе сессионная
  cookie уходит с флагом `Secure`, браузер её по `http://` не сохраняет, и вход
  зацикливается: успешный логин, редирект, снова экран входа. Как только
  появится nginx с TLS — эту строку убрать, иначе cookie ходит по сети открытым
  текстом.
- `DATABASE_URL` в скопированном шаблоне очистите или закомментируйте, если базу
  ещё не подключаете: иначе приложение при старте пойдёт в несуществующий хост.

**`.env.local` — не скрипт.** Ни Docker Compose, ни Next не выполняют в нём
подстановку команд и не разворачивают переменные. Строка

```
AUTH_SESSION_SECRET=$(openssl rand -base64 48)
```

сохранится ровно такой, какая есть — 26 символов текста, и приложение откажется
стартовать. Секрет генерируется **в оболочке**, а в файл попадает результат:

```bash
printf 'AUTH_SESSION_SECRET=%s
' "$(openssl rand -base64 48)" >> .env.local
```

Команда `cat >> .env.local <<EOF … EOF` работает по той же причине: подстановку
делает оболочка до записи. А вот `<<'EOF'` в кавычках — уже нет, как и
копирование строки в текстовый редактор.

Заглушки `QWEN_*` и `PDF_MINERU_*` можно оставить как есть — генерация без них
не работает, но приложение поднимется и вход проверить получится.

Вход — `admin` / `admin` на `/auth/login`. В логах при старте будет заметное
предупреждение об учётных данных по умолчанию: так и задумано, оно умолкнет,
когда будут заданы `AUTH_TEST_USERNAME` и `AUTH_TEST_PASSWORD`.

### 4.3 Если не поднялось

| Что видно | Что это значит |
|---|---|
| `env file … not found` | нет `.env.local`; см. §3.1 |
| `pull access denied for openmaic/app` | образа с таким тегом на хосте нет. `docker images openmaic/app`, при необходимости `docker tag`. Наружу compose не пойдёт — стоит `pull_policy: never` |
| контейнер сразу выходит | смотрите `logs`: проверки конфигурации выполняются до приёма запросов и падают с текстом, объясняющим, чего не хватает |
| `AUTH_SESSION_SECRET is required` | провайдер задан, секрет нет |
| `AUTH_SESSION_SECRET is 26 characters` | в файл попал текст `$(openssl rand -base64 48)`, а не его результат; см. §4.2 |
| `AUTH_PROVIDER=windows is not implemented` | Kerberos ещё не реализован, до фазы 5 используйте `test` |
| статус `unhealthy` | приложение стартовало, но `/api/health` не отвечает; смотрите `logs` |
| вход зацикливается | стенд по http, а `COOKIE_SECURE=0` не задан |

## 5. Приёмочный сценарий

После первого запуска, до того как пускать людей:

1. генерация короткого курса на русском (два-три слайда) — проверяет LLM;
2. озвучка одной сцены — проверяет TTS, если он настроен;
3. импорт `.pptx` с векторной графикой — проверяет вендоренный воркер pdf.js;
4. сцена с формулой — проверяет вендоренный KaTeX;
5. экспорт PPTX и экспорт ZIP — проверяет, что шрифты и ассеты внутри;
6. загрузка PDF — проверяет MinerU.

Если что-то из этого молча не работает — смотрите логи контейнера: пути,
которых нет в контуре, приложение сообщает явно, а не подставляет облако.

## 6. Обновление

```bash
export OPENMAIC_IMAGE_TAG=<новый тег>          # снаружи: сборка и docker save
# перенос, сверка сумм, docker load
docker compose -f docker-compose.contour.yml up -d
```

Старый образ не удаляем, пока новый не отработал рабочий день: откат — это
`OPENMAIC_IMAGE_TAG=<старый тег>` и повторный `up -d`, но только если старый
образ ещё на месте.

Ведите список: какой тег сейчас в контуре, когда загружен, какие теги уже
заняты. Без этого через полгода никто не скажет, что именно работает.

## 7. Что осталось за рамками

- **Фаза 3** — слой идентичности; до неё у приложения нет собственной
  аутентификации, и разграничение держится только на nginx.
- **Фаза 4** — разделение данных между пользователями; до неё серверное
  хранение общее на всех.
- **Фаза 5** — Kerberos/SPNEGO за nginx.
- Конфигурация самого nginx (TLS, таймауты для долгих SSE-ответов генерации,
  заголовки) — отдельная задача, здесь не описана.
