# Пункт 2.4. Речевой тракт на русском — отчёт до начала реализации

Статус: **разведка завершена, интеграция не начата.**
Дата: 2026-09-18. Базовый коммит: `a8726ec`.

---

## 0. Короткий ответ

| Компонент | Русский | Вердикт |
|---|---|---|
| **TTS — VoxCPM2** | **Есть.** Официально 30 языков, русский в списке | Компонент менять не надо. Правится конфигом плюс небольшая доработка нормализации текста |
| **ASR — FunASR** | **Нет** в тех моделях, которые подключены | **Менять компонент.** Рекомендация — локальный Whisper (`faster-whisper`) |
| **Клонирование голоса на русском образце** | Официально заявлено, на практике **не проверено** | Нужен стенд, из кода не оценивается |
| **Браузерный TTS (запасной путь)** | Голос в Windows есть, но приложение его **не выберет** | Дефект детектора языка, чинится одной строкой |

Это не ситуация «продукт теряет основную ценность». Блокер один — ASR, и у него
есть стандартное решение, разворачиваемое в контуре.

## 1. TTS: VoxCPM2 — русский поддерживается

### 1.1 Источник

Карточка модели `openbmb/VoxCPM2` на Hugging Face перечисляет 30 языков дословно:

> Arabic, Burmese, Chinese, Danish, Dutch, English, Finnish, French, German, Greek,
> Hebrew, Hindi, Indonesian, Italian, Japanese, Khmer, Korean, Lao, Malay, Norwegian,
> Polish, Portuguese, **Russian**, Spanish, Swahili, Swedish, Tagalog, Thai, Turkish, Vietnamese

Плюс девять китайских диалектов. Модель — 2 млрд параметров, выход 48 кГц
(AudioVAE V2 со встроенным повышением разрешения), вход референсного аудио 16 кГц.
Заявлены Voice Design (генерация голоса по текстовому описанию, без образца) и
Voice Cloning (базовое по короткому фрагменту, управляемое со стилевой подсказкой,
и «ultimate» — образец плюс его транскрипт).

### 1.2 Что это значит для кода

Адаптер уже есть и готов: `lib/audio/voxcpm.ts`, `lib/audio/tts-providers.ts`.
Поддерживаются три бэкенда (`VOXCPM_BACKENDS`), из них **`vllm-omni` отдаёт
OpenAI-совместимый `/v1/audio/speech`** — ровно то, что нужно для развёртывания
на своём железе. Настраивается переменными:

```
TTS_VOXCPM_BASE_URL=http://<host>:8000/v1
TTS_VOXCPM_API_KEY=            # при необходимости
```

Дописывать адаптер под русский **не нужно**. Более того, если по какой-то причине
VoxCPM2 не подойдёт, в проекте есть готовый обходной путь: провайдер типа
`custom-tts-*` (`lib/audio/types.ts:95`) диспетчеризуется в
`generateOpenAITTS` (`lib/audio/tts-providers.ts:292`), то есть **любой локальный
сервис с OpenAI-совместимым `/v1/audio/speech` подключается без единой строки кода**.

### 1.3 Риски, которые надо закрыть при интеграции

**1. Нормализация текста — главный практический риск.**
В `generateVoxCPMTTS` параметр `normalize` по умолчанию `false`. Внешний
нормализатор VoxCPM ориентирован на китайский и английский. Значит, русский текст
уйдёт в модель «как есть», и числа, сокращения, единицы и даты будут прочитаны
как повезёт: «2026 г.», «3 кг», «§ 4», «т. н.», «XIX в.», «в 1,5 раза».
Для учебного контента это заметно.

Решение: **русская нормализация до синтеза**, на нашей стороне, в пайплайне
озвучки — разворачивать числа в слова с согласованием по роду и падежу,
раскрывать сокращения, расставлять ударения в омографах (`зАмок` / `замОк`,
`бОльший` / `большОй`). Это отдельная задача фазы 2, не конфиг. Объём небольшой,
но её надо явно заложить.

**2. Язык голосовой подсказки.** `buildAutoVoxCPMVoicePrompt`
(`lib/audio/voxcpm.ts`) собирает описание голоса из персоны агента и падает
в английский фолбэк `'natural classroom voice'`. Влияет ли язык описания на
акцент синтезированной русской речи — **из документации не следует, проверяется
только на стенде**.

**3. Латиница и формулы внутри русского текста.** Термины, названия моделей,
единицы СИ и KaTeX-выражения в русской фразе. Как VoxCPM2 читает смешанный
текст — надо слушать, не угадывать.

### 1.4 Что нужно проверить на стенде (не проверяется из кода)

- Разборчивость и естественность русской речи на учебном тексте, 2–3 урока.
- Просодия на длинных предложениях и на перечислениях.
- Чтение чисел, дат, единиц, аббревиатур — до и после нашей нормализации.
- **Клонирование голоса по русскому образцу.** Заявлено, что модель работает на
  30 языках, но качество клона на русском образце это отдельный вопрос;
  из карточки модели он не закрывается.
- Латентность синтеза на вашем железе — от неё зависит фаза 4 (очередь и приоритеты).

## 2. ASR: FunASR — русского нет

### 2.1 Что подключено сейчас

`lib/audio/constants.ts:1300-1312`:

```ts
'funasr-asr': {
  models: [
    { id: 'sensevoice',    name: 'SenseVoiceSmall' },
    { id: 'paraformer',    name: 'Paraformer' },
    { id: 'fun-asr-nano',  name: 'Fun-ASR-Nano' },
  ],
  defaultModelId: 'sensevoice',
  supportedLanguages: ['auto', 'zh', 'en', 'ja', 'ko', 'yue'],
  supportedFormats: ['wav'],
}
```

Русского нет **в самом реестре приложения**. Это не оплошность конфига, а
соответствие моделям:

| Модель | Языки | Русский |
|---|---|---|
| SenseVoiceSmall | китайский, кантонский, английский, японский, корейский | нет |
| Paraformer | китайско-центричная | нет |
| Fun-ASR-Nano | китайский, английский, японский + китайские диалекты и акценты | нет |

Есть мультиязычный чекпойнт **Fun-ASR-MLT-Nano** (800M, заявлено 30+ языков), но
**полного списка языков в доступных источниках я не нашёл** — подтвердить наличие
русского не могу. В реестр приложения он не подключён. Отношу к непроверяемому.

### 2.2 Рекомендация: локальный Whisper

**`faster-whisper` за OpenAI-совместимым `/v1/audio/transcriptions`.** Whisper
поддерживает русский штатно и хорошо; large-v3 на RTX 4090 даёт порядка
70–100× реального времени на коротких репликах — для реплик студента в классе
это с запасом.

Подключается **без доработки адаптера**, тремя способами на выбор:

| Способ | Как | Комментарий |
|---|---|---|
| **A. Провайдер `openai-whisper`** | `ASR_OPENAI_BASE_URL=http://<host>:8000/v1`, `ASR_OPENAI_API_KEY=<любой непустой>` | Реестр уже содержит `'ru'` в `supportedLanguages` (`lib/audio/constants.ts:1099`). Наименьший объём работы |
| **B. Провайдер `custom-asr-*`** | заводится в настройках, `CUSTOM_ASR_DEFAULT_LANGUAGES` включает `'ru'` (`lib/audio/constants.ts:51-65`) | Не занимает «слот OpenAI», если он нужен под другое |
| **C. Провайдер `lemonade-asr`** | `ASR_LEMONADE_BASE_URL=…`, модели Whisper-* | Рассчитан на Lemonade-сервер; брать, только если он и так в контуре |

Рекомендую **A** — меньше всего движущихся частей.

Что всё-таки придётся сделать:

1. **Подписи провайдеров.** В интерфейсе строка будет называться «OpenAI Whisper»
   и показывать логотип OpenAI, хотя сервис локальный. Ввести отдельного
   встроенного провайдера `local-whisper` (реестр + i18n + иконка) — правка на
   уровне констант, адаптер переиспользуется.
2. **Сетевая политика.** Локальный адрес блокируется SSRF-защитой. Нужен
   `ALLOW_LOCAL_NETWORKS=true` (`.env.example:500`) либо адресация сервиса по
   доменному имени внутри compose-сети. Это надо решить осознанно, флаг ослабляет
   защиту глобально.
3. **Формат аудио.** Клиент пишет через MediaRecorder в webm; у `funasr-asr`
   и `lemonade-asr` в реестре стоит `supportedFormats: ['wav']`, у
   `openai-whisper` — webm в списке есть (`lib/audio/constants.ts:1153`).
   Конвертация уже где-то происходит (`lib/audio/wav-utils.ts`) — проверить, что
   выбранный путь не делает лишнего перекодирования.

### 2.3 Что нужно проверить на стенде

- Точность на русской речи в реальных условиях класса: гарнитура, фоновый шум,
  открытый микрофон.
- Поведение на коротких репликах («да», «не понял», «повтори») — Whisper на
  очень коротком аудио склонен галлюцинировать; в адаптере уже есть обработка
  «empty / too short» (`lib/audio/asr-providers.ts`), но пороги надо подобрать.
- Смешанная речь: русский с англоязычными терминами.
- Латентность end-to-end от конца реплики до ответа преподавателя.

## 3. Браузерный TTS — дефект детектора языка

`lib/audio/browser-tts-preview.ts` содержит `detectSpeechLang()`, который
различает ровно три исхода: `zh-CN`, `vi-VN`, `en-US` (добавлено коммитом
`73ea6a7` от 2026-09-17). **Кириллица не распознаётся**, поэтому русская
дикторская реплика будет произнесена английским голосом.

При этом в проекте уже есть готовый детектор кириллицы —
`lib/pbl/legacy/read.ts:318`: `if (/[Ѐ-ӿ]/.test(sample)) return 'ru-RU';`

Плюс `lib/hooks/use-browser-tts.ts:29` по умолчанию `lang = 'zh-CN'`.

Починка — добавить кириллическую ветку в `detectSpeechLang()` и привязку
установленного русского голоса в `lib/playback/engine.ts`, по образцу того, как
это сделано для вьетнамского. Это даёт бесплатный запасной путь озвучки на
рабочих станциях Windows (системный русский голос там есть) — полезно, пока
VoxCPM-сервер не поднят, и как деградация при его недоступности.

## 4. Итоговая рекомендация

1. **TTS: оставляем VoxCPM2.** Разворачиваем бэкенд `vllm-omni`, подключаем через
   `TTS_VOXCPM_BASE_URL`. Дополнительно закладываем задачу «русская нормализация
   текста перед синтезом» — без неё числа и сокращения будут звучать плохо.
2. **ASR: заменяем FunASR на локальный `faster-whisper`** с OpenAI-совместимым
   эндпоинтом. Кода не пишем, кроме отдельной записи провайдера в реестре ради
   честного названия в интерфейсе.
3. **Браузерный TTS: чиним детектор** — дёшево, даёт запасной путь.
4. **Клонирование голоса на русском — под вопросом до стенда.** Если оно не
   взлетит, у VoxCPM2 остаётся Voice Design (голос по текстовому описанию), и
   ролям агентов можно раздать разные синтезированные тембры без образцов.

## 5. Что нужно, чтобы закрыть оставшиеся вопросы

- Стенд с GPU, на котором подняты VoxCPM2 (`vllm-omni`) и `faster-whisper`.
- Ваше решение по `ALLOW_LOCAL_NETWORKS` либо адресации сервисов внутри
  compose-сети.
- Русские образцы голоса, если клонирование нужно как функция.
- Модель нагрузки: сколько одновременных синтезов и распознаваний рассчитываем
  обслуживать — это вход в фазу 4 (квоты, очередь, приоритет интерактива).
