## 1. Что сейчас делает `Dockerfile`

Четыре стадии, multi-stage, итоговый образ — Alpine + Next.js standalone.

| Стадия | Что делает | Сеть нужна |
|---|---|---|
| `base` | `node:22-alpine`, `libc6-compat`, corepack + pnpm 10.28.0 | да (apk, corepack) |
| `deps` | тулчейн сборки нативных модулей, `pnpm install --frozen-lockfile` | да (npm-реестр) |
| `builder` | `pnpm build` = проверка вендоренных ассетов + `next build` | нет |
| `runner` | `node:22-alpine` + cairo/pango/jpeg/giflib/librsvg, пользователь `nextjs` (uid 1001), `/app/data` с правильным владельцем, `node server.js` | да (apk) |

Два аргумента сборки предусмотрены ровно под нашу ситуацию: `ALPINE_MIRROR` и
`NPM_REGISTRY`. Если в организации есть зеркало Alpine и прокси npm (Nexus,
Artifactory), образ пересобирается внутри контура без правок Dockerfile.

Вендоренные ассеты попадают в образ так:

- `public/vendor/katex`, `public/vendor/video-export/fonts`, `public/vendor/gsap.min.js`
  лежат в git → приезжают в `builder` через `COPY . .`;
- `public/vendor/maic-importer` (6,8 МБ, включая воркер pdf.js) генерируется
  в стадии `deps` из `postinstall` → копируется строкой 81;
- шрифты интерфейса — npm-пакеты `@fontsource*`; `next/font/google` не
  используется, за шрифтами в Google никто не ходит.

## 2. Замечания к `Dockerfile`

Состояние на момент разбора; что из этого закрыто — в §5.

### 2.1 Существенные

**(1) Базовый образ и системные пакеты не закреплены.** *(базовый образ закреплён — §5)*
`FROM node:22-alpine` — плавающий тег, `apk add --no-cache …` — без версий.
Через полгода пересборка ради исправления уязвимости даст **другой** образ, и
отличия придётся искать вслепую. Сравните с `render-service/Dockerfile`: база
прибита по `sha256`, пакеты apt указаны точными версиями, индексы берутся из
датированного снапшота `snapshot.debian.org`. Главный образ должен быть не хуже.

**(2) `--mount=type=cache` требует BuildKit.**
Строка 38. На современном Docker включено по умолчанию, но под старым
`docker build` или Podman без поддержки шаг падает с невнятной ошибкой
синтаксиса. Либо фиксируем `DOCKER_BUILDKIT=1` в инструкции, либо дублируем
путь без кэша.

### 2.2 Стоит поправить

**(3) Телеметрия Next.js не отключена.** *(сделано — §5)* Ни в `builder`, ни в `runner` нет
`NEXT_TELEMETRY_DISABLED=1`. В контуре это не сломает работу — запрос отвалится
по таймауту, — но это лишние секунды на старте и исходящий трафик, который
служба безопасности увидит в логах прокси и будет о нём спрашивать.

**(4) `assert-vendor-maic-importer.mjs` проверяет только `index.js`.** *(сделано — §5)* Воркер
pdf.js (`public/vendor/maic-importer/pdf.worker.min.mjs`), добавленный в фазе 2,
ничем не защищён: приедет в образ старый `public/vendor` — сборка пройдёт, а
конвертация EMF-векторов в импортируемом `.pptx` отвалится в рантайме на 404.
Туда же — проверка `public/vendor/katex/katex.min.js`.

**(5) В образе нет `ffmpeg`.** `lib/document/extractors/local-media.ts` ищет
`ffmpeg` и `ffprobe` в `PATH` и, не найдя, корректно сообщает, что извлечение
материалов из аудио и видео недоступно. Деградация честная. Если загрузка
видеолекций в контуре нужна — `apk add --no-cache ffmpeg`, примерно +80 МБ.

**(6) `cairo/pango/jpeg/giflib/librsvg` в рантайме, похоже, лишние.** Стоят ради
`@napi-rs/canvas`, который в исходниках не импортируется ни разу; единственный
зависящий от него пакет — `unpdf`, и то для растеризации страниц, а вызываются
только `extractText` и `extractImages`. Выкидывать сейчас не предлагаю: экономия
десятков мегабайт не стоит риска сломать неочевидный путь.

Побочный вывод, важный для русских документов: системных шрифтов в образе нет,
но они и не нужны — страницы PDF в картинки не рендерятся.

### 2.3 Организационное

**(7) `docker-compose.yml` не задаёт имена образов.** *(сделано — §5)* Ни у `openmaic`, ни у
`render-service` нет ключа `image:`, поэтому compose собирает их под именами
вида `<каталог>-openmaic`. Для `docker save` это значит, что имя переносимого
образа зависит от того, как назван каталог на машине сборки. Нужны явные теги
с версией — иначе на приёмной стороне не проверить, что приехало, и не откатиться.

**(8) Нет healthcheck у приложения.** *(сделано — §5)* У Postgres он есть, у приложения нет —
хотя за nginx это именно то, по чему прокси решает, живой ли апстрим.

## 3. Подключение внешних сервисов контура

Код к этому готов — ничего дописывать не нужно, нужна конфигурация и правки
compose. Разбор по каждому сервису.

### 3.1 Qwen3 (LLM)

vLLM отдаёт OpenAI-совместимый `/v1`, в приложении есть подходящие слоты
провайдеров. Рекомендую слот **`qwen`**: `type: 'openai'`, название и логотип
уже правильные, базовый URL переопределяется.

```
QWEN_BASE_URL=http://<хост-vllm>:8000/v1
QWEN_API_KEY=<ключ, которым запущен vLLM: --api-key>
QWEN_MODELS=<id модели, как её отдаёт /v1/models>
```

Альтернатива — слот `ollama` (`requiresApiKey: false`, ключ не нужен вовсе), но
в интерфейсе он подписан «Ollama» с чужим логотипом, что на русифицированном
корпоративном стенде выглядит странно. Если ключ ставить не хотите — берём
`ollama` и правим подпись через бренд и i18n.

**SSRF-фильтр частному адресу не мешает.** Проверил специально: транспорт LLM
(`lib/ai/providers.ts`) использует диспетчер только ради таймаутов, адресную
политику не применяет. Запрос на `10.x` из серверной конфигурации проходит,
`ALLOW_LOCAL_NETWORKS` для этого включать **не нужно** — см. §3.5.

Отдельно: если включается pro-режим (`OPENMAIC_AGENT_RUNTIME_ENABLED`),
обязателен `MODEL_ROUTES` с явным маршрутом стадии `maic-agent-driver` на
`qwen:<модель>` и `api: "openai-completions"`. Без него ни одна сессия агента не
стартует — запасного пути там намеренно нет.

### 3.2 MinerU

Самостоятельный хостинг поддержан штатно:

```
PDF_MINERU_BASE_URL=http://<хост-mineru>:<порт>
PDF_MINERU_API_KEY=<если сервис требует>
PDF_MINERU_BACKEND=pipeline
```

Важное поведение, которое играет нам на руку: `ALLOW_MINERU_CLOUD_FALLBACK` по
умолчанию выключен, и запрос к самостоятельно развёрнутому MinerU **никогда** не
уходит в облако молча — при неверной конфигурации он падает с явной ошибкой.
Оставляем выключенным; документы контур не покидают.

Приватный адрес здесь тоже проходит: при серверной конфигурации провайдер
считается `managed`, клиентский `baseUrl` игнорируется, а SSRF-проверка
применяется только к клиентскому. Проверено по `app/api/parse-pdf/route.ts`.

### 3.3 PostgreSQL

```
DATABASE_URL=postgres://<пользователь>:<пароль>@<хост>:5432/<база>
```

Четыре вещи, которые надо согласовать с администраторами СУБД:

1. **Приложение само создаёт схему.** При старте `lib/persistence/server-provider.ts`
   вызывает `ensureSchema()`, и таблицы создаются через `CREATE TABLE IF NOT EXISTS`
   в рантайме. Это значит, что пользователю нужны права **DDL** — хотя бы на первый
   запуск. Обычный корпоративный «только DML» здесь не заработает. Варианты:
   выдать `CREATE` на выделенную схему, либо один раз выполнить DDL под
   администратором и потом права урезать (тогда любое обновление приложения,
   добавляющее таблицу, потребует повторения процедуры — это надо зафиксировать).
2. **Отдельная база или отдельная схема.** Разделения по схемам в коде нет,
   префикса таблиц тоже — приложение считает базу своей. Если выделенную базу не
   дают, изоляцию делаем через `search_path` в строке подключения:
   `?options=-c%20search_path%3Dopenmaic`.
3. **TLS и корпоративный CA.** Пул создаётся как `new Pool({ connectionString })`
   без явных TLS-опций, поэтому режим задаётся в самой строке (`?sslmode=require`
   и строже). Проверка сертификата, выпущенного внутренним УЦ, требует доверия на
   уровне Node — то есть `NODE_EXTRA_CA_CERTS` и смонтированный CA-файл. Сейчас
   ни в `Dockerfile`, ни в `docker-compose.yml` места под это нет. Это пробел,
   и он общий для всех HTTPS-сервисов контура, не только для СУБД.
4. **pgvector не нужен.** Векторного поиска и эмбеддингов в проекте нет.
   Расширение в базе не мешает, но и не используется — закладывать под него
   ничего не надо.

### 3.4 Что при этом меняется в `docker-compose.yml`

- сервис `postgres` и том `openmaic-postgres` — **убрать** (внешняя СУБД);
- сеть `default` перестаёт быть «выходом в интернет» и становится путём к
  сервисам контура; комментарий надо переписать, чтобы не вводил в заблуждение;
- `env_file: .env.local` — файл обязан существовать, иначе compose падает;
  нужен шаблон `.env.contour.example` со всеми адресами;
- том `openmaic-data` остаётся: под `/app/data` лежат медиа классов и записи
  об использовании;
- добавить монтирование корпоративного CA (read-only) и `NODE_EXTRA_CA_CERTS`;
- `render-service` остаётся под профилем `video-export` — включаем, только если
  экспорт MP4 нужен.

### 3.5 `ALLOW_LOCAL_NETWORKS` — включать осознанно

Флаг снимает запрет на обращения к частным и loopback-адресам (адреса облачных
метаданных остаются запрещены всегда). Разобрал, кому он реально нужен:

| Путь | Нужен ли флаг |
|---|---|
| LLM через серверную конфигурацию | **нет** |
| MinerU через `PDF_MINERU_BASE_URL` | **нет** (провайдер `managed`) |
| `RENDER_SERVICE_URL` | **нет**, это доверенная операторская настройка |
| Базовый URL, введённый пользователем в настройках браузера | **да**, иначе блокируется |
| Загрузка медиа по URL, который вернул локальный TTS/ASR | **да**, если сервис отдаёт ссылки, а не байты |

Рекомендация: **не включать**. Все провайдеры настраиваем на сервере через
`server-providers.yml`, а неиспользуемые — принудительно отключаем
(`enabled: false`), чтобы они не появлялись в интерфейсе. Флаг оставляем
выключенным до тех пор, пока конкретный сценарий не потребует обратного; тогда
включаем и записываем, ради чего.

## 4. Что переносим

Раз Qwen3, MinerU и СУБД уже в контуре, комплект переноса ужимается до одного
образа плюс, при необходимости, второго:

| Компонент | Переносим | Порядок объёма |
|---|---|---|
| Приложение | образ из этого `Dockerfile` | 500–700 МБ |
| render-service | только если нужен экспорт MP4 | заметно больше (Chromium + FFmpeg) |

Процедура: собрать с явным версионным тегом → `docker save` в tar → посчитать
SHA-256 → перенести → сверить суммы **до** загрузки → `docker load` → поднять
стек → прогнать приёмочный сценарий (генерация короткого курса, озвучка,
экспорт PPTX, экспорт ZIP).

Отдельно нужен ответ на вопрос, который всегда всплывает позже: **как
обновлять.** Схема «пересобрали снаружи — перенесли — загрузили» работает, пока
кто-то ведёт учёт, какая версия сейчас в контуре и какие теги уже заняты.

## 6. Чего я не могу проверить

1. **Саму сборку образа и подключение к сервисам.** На этой машине нет Docker
   (`docker: command not found`), свободно 1,2 ГБ из 233 ГБ. Всё выше —
   статический разбор кода и конфигураций, а не результат запуска.
2. **Как именно запущен Qwen3:** vLLM или Ollama, с `--api-key` или без, какой
   `id` модель отдаёт в `/v1/models`, есть ли HTTPS и чей сертификат. От этого
   зависят три строки в `.env`.
3. **Какие права даст администратор СУБД.** Приложение создаёт таблицы само;
   если политика запрещает DDL приложению, нужна процедура ручного создания
   схемы и договорённость о том, что делать при обновлениях.
4. **Версия и API самостоятельно развёрнутого MinerU** — совместим ли он с тем
   контрактом, который ожидает `lib/pdf/pdf-providers.ts`. Проверяется одним
   запросом на стенде.
5. **Нужны ли в контуре TTS, ASR, генерация изображений и экспорт MP4.**
   По речевому тракту отдельный разбор — [`speech.md`](speech.md).
